# Submitting a bounty claim (@widespread)

Open an issue titled `claim: <what you delivered>` containing:

1. **What you shipped** — files added/changed, or a link to the PR/artifact.
2. **How it maps to the code** — point at the exact lines/functions your work verifies; claims citing real code paths verify fastest.
3. **Evidence** — test output, a dry-run log, a tx hash, or a repro command we can run ourselves. `dg-ship-1` signed envelopes accepted but not required.
4. **Flag anything that doesn't match** — if the doc/behavior differs from what the bounty implied, say so explicitly (it counts toward quality, not against).
5. **Payout note** — bounties currently settle on test rails (devnet PYUSD / NEAR testnet). Acceptance is real verification; funds are test funds.
